## 1. Executive Summary & Product UX Goals

CryptoSentinel is an enterprise-grade, context-aware static cryptographic asset discovery and Post-Quantum Cryptography (PQC) readiness analysis engine.

### Core UX Objectives:
1. **Security Precision & Trust**: Present cryptographic findings with high clarity, precise code context, line numbers, snippets, and rule IDs. Avoid speculative claims or generic SaaS fluff.
2. **Actionable PQC Guidance**: Highlight Shor's and Grover's algorithm vulnerabilities clearly, presenting exact NIST standard migration pathways (FIPS 203 ML-KEM, FIPS 204 ML-DSA) mapped directly to discovered assets.
3. **Restrained Enterprise Aesthetic**: Emphasize technical control using a dark-mode first, slate/indigo cybersecurity visual language with high contrast, crisp typography, tabular dense data views, and contextual badges.
4. **Resilient Data States**: Support zero-finding state, long-running scan progress, malformed response handling, oversized file notifications, and scan error reporting gracefully.

## 2. Full Repository & Backend Inspection Findings

### 2.1 Backend Capability Inventory (Status: IMPLEMENTED)
* **Endpoints**:
  * `GET /health`: Liveness check (`{"status": "ok"}`).
  * `GET /version`: Version information (`{"version": "0.1.0"}`).
  * `POST /api/v1/scan`: Scans local path with optional `language_filters: ["python", "java", "c", "cpp", "pem"]`.
* **Summary Metrics Returned**:
  * `total_files_discovered`, `total_files_scanned`, `files_skipped`, `files_failed`, `total_crypto_assets`, `quantum_vulnerable_assets`.
  * `severity_counts`: `critical`, `high`, `medium`, `low`, `info`.
  * `quantum_threat_counts`: `shor` (vulnerable asymmetric), `grover` (reduced margin symmetric), `none`.
  * `algorithm_distribution`: Map of algorithm string to count (e.g. `{"RSA": 2, "AES": 4}`).
* **Finding Details Returned**:
  * `finding_id` (SHA-256 hash formatted as `crypto-{hash}`), `algorithm`, `category`, `key_length`, `mode`, `padding`.
  * `file_location`: `{ file_path, line_number }`.
  * `evidence`: `{ file_path, line_number, code_snippet, detection_mechanism, matched_rule_id }`.
  * `risk`: `{ severity, reason, confidence, quantum_threat, pqc_recommendation }`.
  * `pqc_recommendation`: `{ target_algorithm, nist_standard, migration_type }` (or `null`).
* **Scan Errors & Skipped Files**:
  * `errors`: List of `{ file, error }`.
  * `skipped_files`: List of `{ file, reason }` (e.g. `oversized`).

### 2.2 Unimplemented / Backend Dependencies (Status: BACKEND DEPENDENCY)
* **CBOM Export (CycloneDX 1.6 / JSON)**: Currently not generated by backend `/api/v1/scan`.
* **Persistent Scan History / Database**: Backend executes scans in-memory and returns immediately; no scan ID persistence, history table, or saved scan lookup.
* **Asynchronous WebSockets / Server-Sent Events**: `/api/v1/scan` is a single synchronous POST request.
* **Remote Git Repository Scanning**: Backend only validates and scans local filesystem paths (`target_path`).

## 4. Page Responsibilities & Component Hierarchy

### 4.1 Dashboard / Scan Launchpad (`/`)
* **Responsibilities**:
  * Input target path (`target_path`) with validation.
  * Multi-select language toggle (`python`, `java`, `c`, `cpp`, `pem`).
  * Run scan trigger with live timer and spinner.
  * Executive Overview Cards (Total Assets, Quantum Vulnerable, Critical Severities, Scan Duration).
  * Vulnerability Breakdowns (Severity distribution bar chart / badges, Quantum Threat breakdown).
  * Top Algorithms Distribution list.

* **Component Hierarchy**:
  ```
  AppLayout
  └── DashboardPage
      ├── ScanConfigCard
      │   ├── PathInput
      │   └── LanguageFilterPills
      ├── MetricGrid
      │   ├── StatCard (Total Assets)
      │   ├── StatCard (Quantum Vulnerable - Shor/Grover)
      │   ├── StatCard (Critical/High Severity)
      │   └── StatCard (Files Scanned / Skipped)
      ├── RiskDistributionSection
      │   ├── SeverityDistributionBar
      │   └── QuantumThreatSummaryCard
      └── TopAlgorithmsTable
  ```

### 4.2 Findings Inventory (`/findings`)
* **Responsibilities**:
  * Dense, tabular listing of all cryptographic findings.
  * Filter by Severity (`critical`, `high`, `medium`, `low`, `info`), Category, Algorithm, and Quantum Threat.
  * Global keyword search across `file_path`, `algorithm`, `matched_rule_id`, and `code_snippet`.
  * Expandable row detail showing complete evidence: code snippet with line highlight, matched rule ID, confidence rating, parameter details (`key_length`, `mode`, `padding`).

* **Component Hierarchy**:
  ```
  AppLayout
  └── FindingsPage
      ├── FindingsFilterBar
      │   ├── SearchInput
      │   ├── SeveritySelect
      │   ├── CategorySelect
      │   └── QuantumThreatSelect
      ├── FindingsTable
      │   ├── FindingTableRow (Collapsed Summary)
      │   └── FindingDetailDrawer / RowExpand (Code Snippet + Evidence + PQC Badge)
      └── TablePagination / ItemCountFooter
  ```

### 4.3 Quantum & PQC Readiness (`/quantum`)
* **Responsibilities**:
  * Isolate assets subject to Shor's algorithm (asymmetric RSA/ECC/DH) and Grover's algorithm (reduced key size symmetric AES).
  * Display Post-Quantum Cryptography Migration Action Cards.
  * Map legacy primitives to FIPS standards:
    * RSA / ECC Digital Signatures $\rightarrow$ **FIPS 204 (ML-DSA-65)**
    * RSA / ECC Key Exchange $\rightarrow$ **FIPS 203 (ML-KEM-768)**
    * Weak Symmetric Key / Mode $\rightarrow$ **FIPS 197 (AES-256-GCM)**
  * Direct replacement vs Hybrid migration path indicators.

* **Component Hierarchy**:
  ```
  AppLayout
  └── QuantumReadinessPage
      ├── QuantumThreatHeader (Shor vs Grover risk posture)
      ├── PqcMigrationOverviewGrid
      │   ├── ShorVulnerabilityCardList
      │   └── GroverVulnerabilityCardList
      └── PqcRecommendationTable (Asset ID -> Current Primitive -> NIST Target Standard -> Action)
  ```

### 4.4 Scan Diagnostics & Errors (`/diagnostics`)
* **Responsibilities**:
  * Audit transparency for files skipped (e.g. `oversized` > 10MB).
  * Surface engine execution errors with file path and error string.
  * Display scan performance metrics (`scan_duration_ms`, `scanner_version`).

* **Component Hierarchy**:
  ```
  AppLayout
  └── DiagnosticsPage
      ├── EngineMetadataCard
      ├── SkippedFilesTable
      └── EngineErrorsTable
  ```

## 5. Design System & Visual Language

### 5.1 Aesthetic Principles
* **Dark-Mode First**: Dark slate background (`#0b0f19`), deep card surface (`#111827`), subtle borders (`#1f2937`).
* **Crisp Technical Contrast**: Text primary (`#f9fafb`), secondary (`#9ca3af`), monospace code (`#38bdf8`).
* **Restrained Severity Palette**:
  * **Critical**: Dark Coral / Rose (`#ef4444`, bg `#451a1a`)
  * **High**: Amber / Orange (`#f97316`, bg `#431d0b`)
  * **Medium**: Golden Yellow (`#eab308`, bg `#3f350c`)
  * **Low**: Emerald Green (`#10b981`, bg `#064e3b`)
  * **Info**: Cyan / Slate (`#06b6d4`, bg `#164e63`)
* **Typography**:
  * Sans-serif interface font: `Inter`, system-ui.
  * Monospace code/asset ID font: `JetBrains Mono`, `Fira Code`, `ui-monospace`.

### 5.2 Component Guidelines
* **Badges**: Pill format, muted background with solid text border, status indicator dot.
* **Code Snippets**: Dark code blocks with line numbers, highlighted syntax string, copy snippet button.
* **Tables**: Compact padded cells, sticky headers, hover highlights, clean empty state message.
* **Buttons**: Solid primary indigo (`#4f46e5`), outline secondary with dark slate hover state, loader state on async operations.

## 6. Comprehensive UI States

| UI State | Trigger Condition | Visual Representation |
|---|---|---|
| **Uninitialized / Ready** | Page loaded, no scan executed | Clear input form, informative onboarding placeholder, helpful example paths |
| **Scanning / Loading** | `POST /api/v1/scan` in progress | Pulse indicator, active scan timer, disabled input controls |
| **Success / Results** | `200 OK` scan response | Metrics animated in, findings populate tables, summary charts render |
| **Empty Results** | `200 OK` with 0 crypto assets | Green check banner: "No Cryptographic Assets Detected", scan metrics summary |
| **Oversized / Skipped Files** | `skipped_files.length > 0` | Amber warning badge in nav header with drawer shortcut to `/diagnostics` |
| **API / Target Path Error** | `400 Bad Request` or `500` | Red alert box displaying `error.code` and `error.message` with retry action |
| **Network Disconnected** | Backend uncommunicative | System offline banner: "Backend API (localhost:8000) unreachable" |

## 7. Responsive Strategy

* **Desktop Wide (1280px+)**: Multi-column dashboard layout, full findings table with inline code drawer, dual-pane PQC migration view.
* **Tablet / Medium (768px - 1024px)**: Stacked metric grid (2x2), horizontal scrolling tables with sticky columns.
* **Mobile (< 768px)**: Single column stack, collapsed navigation drawer, card-based findings representation instead of dense table rows.
